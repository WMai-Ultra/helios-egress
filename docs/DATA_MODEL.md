# 数据模型

本文描述键值存储结构、快照语义与跨接入点一致性策略。

---

## 1. 存储分层

| 层 | 位置 | 生命周期 | 作用 |
|---|---|---|---|
| 接入点快照 | 边缘节点本地缓存 | 短（随请求刷新） | 同一接入点内所有实例共享的最新状态 |
| 全局快照 | 键值存储 | 中（按周期覆写） | 跨接入点一致性来源 |
| 持久配置 | 键值存储 | 长 | 订阅用户库 |

读取顺序：**接入点快照 → 全局快照 → 空值**。任何一层缺失都不影响上层可用性。

---

## 2. 快照字段

| 字段 | 类型 | 语义 |
|---|---|---|
| `timestamp` | 数值 | 快照生成时刻（上游上报时刻，非读取时刻） |
| `data` | 数组 | 原始计数样本（用于逐用户与逐入站的增量计算） |
| `pings` / `jitters` / `losses` | 对象 | 边缘接入点分段指标 |
| `edgeRtt` / `edgeRttHist` | 数值 / 数组 | 出口节点 ↔ 边缘的单次往返测量值与历史 |
| `colos` | 对象 | 分段实测落点 |
| `nodeStatus` | 数组 | 中继节点可达性与 RTT |
| `userTraffics` | 对象 | 逐用户计量（上下行、累计、速率） |
| `userLastSeen` | 对象 | 逐用户最后活跃时刻（权威值，只增不减） |
| `onlineUsers` / `onlineUsersAt` | 数组 / 数值 | 活动连接清单与其落库时刻 |
| `history15m` | 数组 | 15 分钟滑动窗口采样点 |
| `bwPeak` | 对象 | 15 分钟与当日带宽峰值 |
| `telemetry` | 对象 | 节点设备遥测（电源、温度、空口信号、进程状态等） |

## 3. 一致性策略

### 3.1 问题

边缘为多接入点部署：上报只落到其中一个接入点，其余接入点读到的是全局快照。
若不加以约束，各接入点会对同一业务对象产生**不同的推断结果**。

### 3.2 规则

| 规则 | 内容 |
|---|---|
| R1 | 状态类字段**只允许来自上游权威源**，禁止由本地观察量推导 |
| R2 | 一致性判据**只使用快照内字段**（如"快照时刻 − 权威时刻"），保证同快照同结果 |
| R3 | 单调量（累计计量）取最大值；**状态量不得取最大值**（取最大值会让失效数据永久生效） |
| R4 | 权威源变更时**整表重建**，而非与历史值逐项比较 |
| R5 | 缺字段时按"上游 → 本地快照 → 全局快照"顺序回落，不回落到推测值 |

### 3.3 典型反例（历史缺陷，已修复）

| 反例 | 后果 |
|---|---|
| 用"计数是否增长"判定会话状态 | 同一用户在 A 接入点为离线、B 接入点为在线，刷新即跳变 |
| 状态字段与历史值取最大值 | 失效数据永久覆盖权威值，观测值越修越偏 |
| 回退保护覆盖整个对象 | 计量回退的同时把会话状态一并回退，在线用户被判为离线 |

## 4. 计量模型

| 项 | 规则 |
|---|---|
| 计数来源 | 代理核心与入站的累计计数 |
| 基线 | 持久化基线 + 增量；计数回绕或重置时按增量补偿 |
| 输出 | 逐用户上下行、累计、瞬时速率 |
| 约束 | 累计值单调不减 |

---

## 5. 写入节流

| 项 | 说明 |
|---|---|
| 全局快照写入周期 | 与免费额度上限对齐（约 2.5 min 一次） |
| 用户库写入 | 仅在内容变更时写入 |
| 遗留键 | 早期版本遗留的键在确认无引用后清理 |

---

## 6. 字段命名约定

| 约定 | 示例 |
|---|---|
| 时刻类字段以 `At` 结尾 | `onlineUsersAt`、`statUserBytesAt` |
| 历史数组以 `Hist` 结尾 | `edgeRttHist` |
| 逐实体映射以实体名复数命名 | `userTraffics`、`userLastSeen` |
| 单位在键名中体现 | `rateDown`（字节/秒）、`ageS`（秒） |

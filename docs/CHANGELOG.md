# 变更记录

本记录按**工程口径**登记：每条包含现象、根因、处置与验收方式。
所有条目均已在线验证；未验证项不登记。

## 2026-10-05 · 观测一致性修复批次

### 1. 会话状态与最后活跃时刻跨接入点不一致

| 项 | 内容 |
| --- | --- |
| 现象 | 同一位离线用户在不同接入点显示不同时间；多个用户显示同一时间；刷新一次变一次 |
| 根因 | ① 节点侧活动连接清单解析规则与上游返回结构不符，清单恒为空；② 节点侧最后活跃时刻文件残缺，部分用户无权威值；③ 边缘以"本地计数是否增长"判定会话状态，属各接入点独立推断；④ 状态字段与历史值取最大值，失效数据永久生效；⑤ 回退保护覆盖整个对象，把会话状态一并回退 |
| 处置 | ① 按上游真实结构解析清单；② 活跃时刻改为全员持久维护并从全员表回灌，只增不减；③ 改为三级判据（权威清单 → 快照时刻与权威时刻比对 → 启发式回落），判据只使用快照内字段；④ 权威源到达时整表重建而非取最大值；⑤ 回退保护仅回退计量字段 |
| 验收 | 连续 16 次请求覆盖 6 个接入点：离线用户状态与时刻**各只有 1 个取值**；在线用户保持在线；界面观测值与真实活跃历史一致 |

### 2. 观测面口径不统一

| 项 | 内容 |
| --- | --- |
| 现象 | 状态卡片显示"长期无会话"，同页表格显示在线；卡片内两行时间互相矛盾；首屏与轮询结果闪跳 |
| 根因 | 表格状态列、卡片右下角时刻、首屏服务端渲染各自使用不同判据（其中两处使用本地观察量） |
| 处置 | 三处统一为同一权威判据；在线文案区分"实时确认"与"上游确认"；首屏与轮询使用同一判据 |
| 验收 | 同页各视图状态一致；首屏与轮询结果不再跳变 |

### 3. 指标新鲜度呈现不准确

| 项 | 内容 |
| --- | --- |
| 现象 | 顶部时间显示与推送节拍不符；节点矩阵中正常节点被标记为数据老化 |
| 根因 | 顶部时间按固定轮询周期计算；节点老化阈值按固定秒数判定，未考虑一轮巡检的实际时长 |
| 处置 | 顶部时间改用实时推送年龄；节点老化改为**按轮次**判定（中位间隔 × 节点数，并设上下限） |
| 验收 | 推送年龄与实际节拍一致；正常巡检周期内不再出现误标 |

### 4. 高频采集模式的资源占用

| 项 | 内容 |
| --- | --- |
| 现象 | 高频模式下轮询密度过高，指标重复计算且无新增信息 |
| 根因 | 采用固定短周期轮询，与上报节拍不匹配 |
| 处置 | 改为与上报节拍对齐的槽位采集（每个槽位双采样），取消冗余轮询 |
| 验收 | 高频模式样本量提升，边缘侧请求量下降 |

### 5. 探测并发争抢

| 项 | 内容 |
| --- | --- |
| 现象 | 4 个采集进程并发探测，峰值占用终端设备上行，影响业务转发 |
| 根因 | 各脚本独立调度，无全局并发约束 |
| 处置 | 引入基于目录原子性的许可机制，**硬性上限 2**；含持有者退出回收与等待超时日志 |
| 验收 | 峰值并发 = 2；无许可等待超时告警；业务转发无抖动 |

### 6. 跨接入点数据获取

| 项 | 内容 |
| --- | --- |
| 现象 | 非节点直连的接入点数据年龄偏大 |
| 根因 | 仅依赖本接入点缓存，全局同步缺失 |
| 处置 | 增加全局快照（按配额节流写入）与按顺序回落读取 |
| 验收 | 各接入点数据年龄收敛到同一量级 |

### 6.1 全局快照写入超额（2026-10-05 补充）

| 项 | 内容 |
| --- | --- |
| 现象 | 远离出口节点的接入点偶尔读到停更的全局快照；当天晚些时候更明显 |
| 根因 | 全局快照的去重使用「快照键 + 桶标记键」共 **2 次写入 / 2.5 分钟**，折算 **1152 次/天**，超过键值存储免费额度（1000 次/天）；超出部分被异常捕获静默丢弃 |
| 处置 | 去重信息内联进快照自身（写入时刻 / 写入接入点 / 当日写入计数），改为**单键写入**；写入条件三条同时满足：间隔 ≥150 秒、本接入点为上一版写入者（或上一版失联 ≥600 秒）、当日写入未达硬上限 900 次。稳态下同时只有一个接入点写入 |
| 观测 | 当日写入计数与写入接入点通过 `/api/live` 暴露（`kvWriteDay` / `kvWriterColo`），可随时对照额度 |
| 验收 | 当日写入 ≤900 次（实时延探测率约 576–720 次/天）；快照更新间隔稳定在 120–150 秒 |

### 6.2 跨接入点读缓存下调

| 项 | 内容 |
| --- | --- |
| 现象 | 无实时数据的接入点，数据年龄比快照本身还要旧最多 60 秒 |
| 根因 | 读取全局快照时使用 `cacheTtl: 60`，与快照写入周期叠加 |
| 处置 | `cacheTtl` 由 60 秒下调至 **30 秒**（官方规定的最小值；0 会被拒绝） |
| 验收 | 无实时数据接入点的数据年龄上限由约 210 秒降至约 180 秒 |

### 7. 订阅结构规范化

| 项 | 内容 |
| --- | --- |
| 现象 | 订阅分组冗杂，节点命名含实测落点，时延探测目标路径过长 |
| 根因 | 历史演进遗留；命名与探测目标未随架构调整 |
| 处置 | 分组精简为三个（代理 / 自动优选 / 故障转移）；节点统一编号命名；探测目标改为节点侧内置 204 响应；启用统一时延口径 |
| 验收 | 各客户端均可正常加载；时延探测值下降；节点数量与命名一一对应 |

### 8. 传输多路复用实验（已回滚）

| 项 | 内容 |
| --- | --- |
| 现象 | 启用多路复用后部分客户端连接被强制关闭 |
| 根因 | 与当前协议的隧道复用行为不兼容 |
| 处置 | 评估后**回滚**，保持默认多路复用策略，不再启用该实验项 |
| 验收 | 客户端连接稳定，无强制关闭告警 |

# 部署指南

本文描述从零部署本平台的前置条件、步骤与验收标准。

---

## 1. 前置条件

| 类别 | 要求 |
|---|---|
| 边缘账号 | 具备 Workers 与键值存储（KV）权限 |
| 键值存储 | 已创建命名空间，用于存放订阅用户库与全局快照 |
| 反向隧道 | 已创建隧道并取得隧道凭据文件 |
| 出口节点 | 具备 root 权限的 Android 设备，可长期供电与联网 |
| 本地工具 | Python 3.8+；部署脚本依赖标准库，无需额外包 |

---

## 2. 配置项

全部配置集中在 `.env`（由 `.env.example` 复制而来）：

| 键 | 说明 | 是否必填 |
|---|---|---|
| `CF_ACCOUNT_ID` | 边缘账号标识 | 是 |
| `CF_API_TOKEN` | 部署用令牌（仅需 Workers 与 KV 权限） | 是 |
| `CF_KV_NAMESPACE_ID` | 键值存储命名空间标识 | 是 |
| `CF_SCRIPT_NAME` | 边缘脚本名 | 是 |
| `WORKER_HOST` | 边缘对外主机名 | 是 |
| `TUNNEL_HOST` | 隧道主机名 | 是 |
| `TUNNEL_ID` | 隧道标识 | 是 |
| `VLESS_UUID` | 传输凭据 | 是 |
| `ADMIN_PASSWORD` | 监控台访问口令 | 是 |
| `SYNC_SECRET` | 节点 ↔ 边缘同步密钥 | 是 |
| `DAY_TZ` | 日界线时区（影响当日统计切分） | 否（默认 UTC） |

> 部署脚本会在部署前校验必填项，缺项直接终止，不会以半配置状态上线。

---

## 3. 部署步骤

### 3.1 边缘

```bash
cp .env.example .env
# 编辑 .env，填入上表各项

python tools/cf_deploy.py
```

部署脚本行为：

1. **备份**：把当前线上脚本备份为带时间戳的文件；
2. **注入版本**：把版本号写入脚本，便于在监控台核对当前线上版本；
3. **上传**：调用边缘接口完成部署；
4. **失败回滚**：任一步失败则按备份回滚，不回滚成功不退出。

### 3.2 出口节点

1. 推送节点侧脚本与配置样例至设备；
2. 填入隧道凭据、传输凭据与边缘地址；
3. 通过统一入口启动：

```bash
sh run_daemon.sh
```

启动顺序固定（守护进程 → 上报调度 → 各采集脚本），顺序错误会导致遥测缺段。

---

## 4. 验收标准

| 编号 | 验收项 | 判定方法 |
|---|---|---|
| A1 | 边缘可访问 | 订阅地址返回 200，且返回内容为有效订阅格式 |
| A2 | 隧道已建立 | 监控台"节点设备段"显示为活跃 |
| A3 | 遥测连续 | 监控台数据年龄持续小于 30 s，且无长时间空窗 |
| A4 | 会话判定有效 | 连接客户端后，对应用户状态在 10 s 内变为会话活跃 |
| A5 | 分段指标齐备 | 五段指标均有实测值或明确的空值（不得出现推测值） |
| A6 | 并发受限 | 节点侧探测并发不超过 2，无许可等待超时告警 |
| A7 | 计量单调 | 逐用户累计流量在整轮观察期内不减 |

---

## 5. 回滚

| 对象 | 方式 |
|---|---|
| 边缘 | 使用 `tools/cf_deploy.py` 生成的备份文件重新部署 |
| 节点侧脚本 | 覆盖回备份文件；脚本按轮次重新执行，无需重启服务 |
| 配置 | 恢复备份配置后重新启动节点守护进程 |

回滚为**可逆操作**：备份文件保留在项目目录与节点本地目录中，均可直接复用。

# 运维手册

本文给出日常巡检、值班判定、常见故障处置与回滚流程。

---

## 1. 值班巡检项

| 周期 | 巡检项 | 正常判据 | 异常处置 |
|---|---|---|---|
| 5 min | 遥测数据年龄 | 持续 < 30 s | 见 §3.1 |
| 5 min | 节点设备段状态 | 活跃 | 见 §3.2 |
| 15 min | 隧道异常累计 | 无增长 | 见 §3.3 |
| 15 min | 探测并发 | 峰值 ≤ 2 | 见 §3.4 |
| 1 h | 键值存储写入量 | 低于当日额度分配值 | 见 §3.5 |
| 1 h | 逐用户计量 | 单调不减 | 见 §3.6 |
| 每日 | 版本号 | 与预期部署版本一致 | 见 §3.7 |

---

## 2. 监控界面判读

监控台顶部展示三个时间量，含义严格区分：

| 字段 | 含义 | 数据来源 |
|---|---|---|
| 遥测推送 | 边缘最后一次收到上报的时间 | 边缘侧记录 |
| 数据年龄 | 快照年龄（反映数据新鲜度） | 快照时间戳 |
| 版本 | 当前线上脚本版本 | 部署时注入 |

**判读纪律**：数据年龄与版本必须同时看。数据年龄小但版本不符，说明部署未生效；
版本正确但数据年龄持续增长，说明节点侧上报中断。

## 3. 常见故障处置

### 3.1 数据年龄持续增长

**现象**：数据年龄 > 60 s 且持续增长。

**处置顺序**：

1. 核对节点设备段状态：若同时为不活跃，转 §3.2；
2. 核对上报调度进程是否在运行；
3. 核对最近一次上报载荷是否完整（字段缺失会导致聚合层透传空值）；
4. 恢复后观察一个上报周期（6 s），确认数据年龄回落。

### 3.2 节点设备段不活跃

1. 检查隧道客户端进程状态；
2. 重启隧道客户端（**中断窗口约 3 s**，符合 <10 s 的服务中断约束）；
3. 若仍不活跃，检查终端设备接入网上行是否可用；
4. 恢复后在监控台确认五段指标逐段回填。

### 3.3 隧道异常累计增长

1. 取增长时间点，与终端设备接入网的链路质量曲线对齐；
2. 若与丢包/抖动峰值重合 → 判定为接入网质量导致，记录不处置；
3. 若独立于接入网质量 → 检查边缘侧到节点的路径与协议参数；
4. 任何隧道参数变更前必须记录基线，便于回滚比对。

### 3.4 探测并发超限

并发由节点侧许可机制硬性限制为 2。若出现许可等待超时告警：

1. 检查是否有采集脚本被重复拉起（重复实例会争抢许可）；
2. 检查单个探测的超时设置是否过长（长超时会占住许可）；
3. 处置后确认日志中不再出现等待超时。

### 3.5 键值存储写入接近额度

1. 核对全局快照写入周期是否被误改（周期决定了日写入量的量级）；
2. 清理遗留键（早期版本可能残留已不再使用的键）；
3. 变更前后各记录一次写入计数，确认节流生效。

### 3.6 计量出现回落

逐用户累计流量**物理上不可逆**，出现回落即为缺陷。处置：

1. 定位该用户基线文件是否被重置；
2. 检查计量基线补偿逻辑是否生效；
3. 确认修复后，该用户在观察期内单调不减。

### 3.7 版本不符

1. 重新执行部署流程；
2. 若版本仍不更新，检查部署令牌权限与脚本名配置；
3. 部署失败时**不要手工修补线上脚本**，直接使用备份回滚后重试。

## 4. 变更管理

| 规则 | 说明 |
|---|---|
| 先备份 | 任何线上变更前必须留存带时间戳的备份 |
| 小步变更 | 一次只改一类问题，便于归因 |
| 变更即验证 | 变更后必须按验收标准逐条复核（见 `DEPLOYMENT.md` §4） |
| 中断预算 | 涉及重启的变更，服务中断必须 < 10 s，且需记录实测值 |
| 可回滚 | 每个变更点必须有明确回滚路径与备份位置 |

---

## 5. 观测面纪律

1. **不推测**：无法测量时输出空值；禁止用历史值或经验值填补；
2. **不各算一套**：所有状态由同一份快照渲染，前端不参与状态推导；
3. **可归因**：任何指标都能回答"由谁、在何时、以何种方式测得"；
4. **口径变更需留痕**：指标的测量方式一旦调整，必须在变更记录中说明原因与新口径。
